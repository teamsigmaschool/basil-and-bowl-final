## Lint and build

```bash
npm run lint
npm run build
npm run preview
```

Linting uses ESLint (React Hooks + React Refresh rules), matching the
current `npm create vite@latest -- --eslint` scaffold. `npm run build`
outputs a production bundle to `dist/`. `npm run preview` serves that
bundle locally so you can sanity-check the built app before deploying.

## Instructor-led state vs. final solution

This one project folder holds the final solution (both challenges done).
No branch or tag switching is needed to teach or follow the session; the
two states are just "the code as it is now" minus the two challenge
additions, described here plainly:

**Instructor-led state** (what students should have before either
challenge): `App.jsx` wraps the app in `BrowserRouter` / `Routes`, with a
`Route` for `Home` at `/` and a `Route` for `Menu` at `/menu`. `NavBar.jsx`
has `NavLink`s for Home and Menu only (no About link). `Home.jsx`'s "View
Menu" button uses `useNavigate`. There is no `About.jsx`, no `/about`
route, and no `NotFound.jsx` or catch-all route yet, so an unmatched path
like `/anything` renders a blank area under the nav bar (this is also the
common-mistake demo state, see below).

**Final solution** (current state of every file in this project): adds
`src/pages/About.jsx` with a `Route` at `/about` and a matching `NavLink`
(Challenge 1), and `src/pages/NotFound.jsx` with a catch-all `Route`
(`path="*"`, must be the last `Route` in the list) plus a `Link` back to
`/` (Challenge 2).

To present the instructor-led state live, the simplest approach is to
comment out or temporarily delete the About/NotFound `Route` entries and
the About `NavLink` before the session, then restore them (or `git
checkout .`) once challenges begin. This project's git history also has a
tagged commit for each build step (`git log --oneline --all --decorate`)
kept purely as an internal build record; presenting from tags is not
necessary and students never need to know they exist.

## Empty menu state

`src/pages/Menu.jsx` checks `MENU_ITEMS.length === 0` and shows a "Our
menu is getting ready" message with the nav bar and branding still
visible, instead of an empty page, if the data array is ever cleared.
This was verified with an empty array and restored to the full six-item
menu for the final solution; no fetching, loading state, or filtering was
added, it is a single ternary in the existing supplied menu code.

## Deploy to Vercel

1. Push this project to a new GitHub repository (see placeholder above).
2. In Vercel, **Add New → Project**, then import that GitHub repository.
3. Vercel auto-detects the Vite framework preset. Build command
   `vite build` (equivalent to `npm run build`) and output directory
   `dist` are filled in automatically; no changes are needed.
4. Click **Deploy**. Vercel builds the project and gives it a public
   `<something>.vercel.app` URL.
5. Open `/menu` directly (not just by clicking the nav link) and refresh
   the page. This project's `vercel.json` rewrites every path to
   `index.html` so React Router can take over client-side; without it,
   a direct visit or refresh on `/menu` or `/about` returns a 404 from
   Vercel before React ever loads.
6. After building either challenge, push again; Vercel redeploys
   automatically on every push to the connected branch. Re-check `/about`
   and an unmatched path (e.g. `/nowhere`) on the live URL once that
   push finishes.
